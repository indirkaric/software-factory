---
name: new-crud-module
description: Ordered checklist for scaffolding a brand-new, persistence-backed domain module (entity through controller and tests) in this repo's layered style, starting from the reference module. Use when starting a module from zero.
---

Follow `CLAUDE.md` for the package map and the agent rules. Every service generated by the
factory contains one complete reference module for its first domain (`{{Domain}}`): entity,
changeset, Criteria repository with paged list, projections, validators, operation services,
mapper, response creators, controller and a test for each. A new module is that module copied
and renamed, then adapted. Don't write a layer from memory when the reference has it.

Steps 1–7 are root-level and shared; 8–10 go under `modules/<domain_package>/`
(`<domain_package>` = snake_case of the entity name). Every new package gets a
`package-info.java`. Pull in the layer's skill when you reach it.

1. `entity/<Entity>` extends `ExternalEntity` (`entity-and-liquibase-conventions`).
2. `liquibase/changes/NNNN-create-<table>-table.sql` + its `<include>` in `changelog.xml`:
   table, unique index on `entity_id`, the four audit columns, a rollback.
3. `repository/projection/<Domain>ItemProjection` (list columns) and `<Domain>Projection`
   (detail columns), records (`repository-conventions`).
4. `service/model/<Domain>ListFilter` record, `repository/I<Domain>Repository` +
   `repository/impl/<Domain>Repository` on the Criteria API with the metamodel.
5. `service/validator/Base<Domain>DataValidator` + one interface/impl per write operation
   (`service-layer-conventions`).
6. `service/<domain_package>/I<Domain>Service` (reads), `ICreate…`, `IModify…`, `IDelete…` + impls.
7. `dto/<Domain>DTO` and `mapper/I<Domain>Mapper`.
8. `modules/<domain_package>/model/`: `Create<Domain>Request`, `Modify<Domain>Request`,
   `<Domain>ListRequest` (classes, validated and normalized), `<Domain>Response`,
   `<Domain>ItemResponse`, `<Domain>ListResponse` (records).
9. `modules/<domain_package>/service/I<Domain>ResponseCreatorService`,
   `I<Domain>ListResponseCreatorService` + impls.
10. `modules/<domain_package>/<Domain>Controller` (`controller-conventions`).
11. Permissions: reuse `Constants.Authority` or add scopes (`permissions-and-tokens`).
12. Tests for every class from steps 5–10 plus the mapper (`testing-conventions`), then
    `mvn -o verify` (tests, JaCoCo, checkstyle). Not done until it passes.
13. Prove it running: boot the service against the development stack and call every endpoint
    once, plus one error case per rule; keep each request body and response (status + body).

Only the reference module's shapes are mandatory; drop what the new module doesn't need (no
delete endpoint → no delete service, validator or test). If the module has no local entity, use
`new-proxy-module` instead.
